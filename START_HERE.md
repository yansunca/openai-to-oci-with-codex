# OCI Generative AI Setup Guide

Use this guide **after Codex performs the migration in Step 3 of the [main README](README.md)**.

The migrated application requires:

```text
OCI_GENAI_API_KEY=...
OCI_OPENAI_BASE_URL=...
OCI_GENAI_PROJECT_ID=...
OCI_MODEL=...
```

Never commit your real API key or local `.env`.

## 1. Get `OCI_GENAI_API_KEY`
In OCI Console, open **Generative AI → API Keys**, create a key in the demo compartment, select the required model/scope access, and securely save one generated key. A key resource can support multiple keys for rotation; the application needs only one valid key.

## 2. Get `OCI_OPENAI_BASE_URL`
Use:

```text
https://inference.generativeai.<region>.oci.oraclecloud.com/openai/v1
```

Replace `<region>` with your actual OCI region. Do not leave the placeholder in `.env`.

## 3. Get `OCI_GENAI_PROJECT_ID`
In OCI Console:
1. Open **Generative AI → Projects**.
2. Create or select a project in the demo compartment.
3. Copy the Project OCID.

It looks similar to:

```text
ocid1.generativeaiproject.oc1....
```

Do not hard-code it in `app.py`.

## 4. Get `OCI_MODEL`

Model availability varies by OCI region. **Do not copy a model ID from an example without confirming that it is available in your region.**

1. In the OCI Console, confirm the active region in the top navigation.
2. Open **Generative AI**.
3. Open the **Project** you are using for this demo.
4. Check the Project's **How to use** experience or generated OpenAI-compatible sample code.
5. Select a model available to that Project/region.
6. Copy the exact model identifier shown in the sample.

For example, if OCI shows:

```python
response = client.responses.create(
    model="provider.model-id",
    input="Hello",
)
```

then configure:

```text
OCI_MODEL=provider.model-id
```

The value must be copied exactly. Do not assume a model available in one OCI region is available in another.

You can also confirm current regional model availability in Oracle's public documentation:

https://docs.oracle.com/en-us/iaas/Content/generative-ai/model-endpoint-regions.htm

Avoid hard-coding a model ID into the application. The selected model belongs in `OCI_MODEL`.

## 5. Configure `.env`
Codex should update `.env.example` during migration. Then run:

```bash
cp .env.example .env
```

Fill in:

```text
OCI_GENAI_API_KEY=<your-secret>
OCI_OPENAI_BASE_URL=https://inference.generativeai.<your-region>.oci.oraclecloud.com/openai/v1
OCI_GENAI_PROJECT_ID=ocid1.generativeaiproject....
OCI_MODEL=<your-model-id>
```

Confirm `.env` is ignored:

```bash
git status --ignored
```
