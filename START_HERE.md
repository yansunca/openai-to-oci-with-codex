# OCI Generative AI Setup Guide

Use this guide **after Codex performs the migration in Step 3 of the [main README](README.md)**.

This POC uses **OCI IAM user-principal authentication** with your standard OCI CLI configuration.

The migrated application needs:

```text
OCI_OPENAI_BASE_URL=...
OCI_GENAI_PROJECT_ID=...
OCI_MODEL=...
OCI_CONFIG_PROFILE=DEFAULT
```

Authentication comes from your OCI CLI profile in `~/.oci/config`. Set `OCI_CONFIG_PROFILE` to the profile name you want to use.

Never commit `.env`, `~/.oci/config`, OCI private keys, or other credentials.

## 1. Configure OCI CLI Authentication

Make sure OCI CLI authentication already works on your machine.

The migration uses the OCI CLI profile named by `OCI_CONFIG_PROFILE`.

If `OCI_CONFIG_PROFILE` is not set, use `DEFAULT`.

Your profiles live in:

```text
~/.oci/config
```

Keep the OCI config and referenced signing key outside this repository.

## 2. Get `OCI_OPENAI_BASE_URL`

Use the exact OpenAI-compatible endpoint shown by your OCI Generative AI Project's **How to use** sample.

Pattern:

```text
https://inference.generativeai.<region>.oci.oraclecloud.com/openai/v1
```

Example for Ashburn:

```text
https://inference.generativeai.us-ashburn-1.oci.oraclecloud.com/openai/v1
```

## 3. Get `OCI_GENAI_PROJECT_ID`

In OCI Console:
1. Open **Generative AI → Projects**.
2. Create or select the Project used for the demo.
3. Open **How to use**.
4. Copy the exact Project OCID shown in the OpenAI-compatible example.

Example shape:

```text
ocid1.generativeaiproject.oc1....
```

## 4. Get `OCI_MODEL`

Model availability varies by region.

1. Confirm your active OCI region.
2. Open **Generative AI → Projects**.
3. Open your Project and **How to use**.
4. Choose a model supported for that Project/region.
5. Copy the exact model identifier shown in the sample.

Do not guess the model ID.

Oracle's regional model availability reference:

https://docs.oracle.com/en-us/iaas/Content/generative-ai/model-endpoint-regions.htm

## 5. Configure the Local Environment

Codex should update `.env.example` during migration. Copy it:

```bash
cp .env.example .env
```

Fill in:

```text
OCI_OPENAI_BASE_URL=https://inference.generativeai.<your-region>.oci.oraclecloud.com/openai/v1
OCI_GENAI_PROJECT_ID=ocid1.generativeaiproject....
OCI_MODEL=<your-model-id>
OCI_CONFIG_PROFILE=DEFAULT
```

Export the configuration into your shell:

```bash
set -a
source .env
set +a
```

Both the migrated application and `verify_oci_iam.py` read normal process environment variables.

Confirm `.env` remains ignored:

```bash
git status --ignored
```
